# Raw genotype formats and Beagle validation contract

PredictProR treats raw genotype import as a separate release gate. A successful
file read is not sufficient: allele orientation, dosage, missingness, sample and
marker identity, external-process status, and the post-Beagle import must agree.

## Public API

```r
# Raw VCF, with a user-managed Beagle JAR
beagle_result <- impute_genotypes_with_beagle(
  input = "trial.vcf.gz",
  input_format = "vcf",
  output_prefix = "results/trial",
  beagle_jar = Sys.getenv("PREDICTPRO_BEAGLE_JAR"),
  nthreads = 4,
  seed = 20260815
)

# Raw HapMap: convert to VCF 4.3, run Beagle, and return numeric genotypes
beagle_result <- impute_genotypes_with_beagle(
  input = "panel.hmp.txt.gz",
  input_format = "hapmap",
  output_prefix = "results/panel",
  invalid_call = "error"
)

# The same preprocessing can be requested inside any model_execute workflow
fit <- model_execute(
  pheno_data = phenotype,
  hapmap_file_name = "panel.hmp.txt.gz",
  hapmap_file_path = "raw-data",
  imputation_method = "beagle",
  beagle_options = list(
    beagle_jar = Sys.getenv("PREDICTPRO_BEAGLE_JAR"),
    output_prefix = "results/panel",
    nthreads = 4,
    seed = 20260815
  ),
  response = "Yield",
  gen_name = "GID",
  GS_model = "Ridge_Regression"
)
```

For reproducible analyses, supply `beagle_jar` explicitly or set
`PREDICTPRO_BEAGLE_JAR`, record the JAR checksum, set `seed`, and retain the
returned Beagle and wrapper logs. If no JAR is supplied, PredictProR downloads
the pinned official `29Oct24.c8e` build into the user cache. It never installs
Java or changes the operating system. A genetic map is not generated by
default: supply a validated `map_file` when a measured or reference map is
available. Set `generate_map = TRUE` only when the documented 1 cM/Mb linear
assumption is scientifically appropriate for the analysis.

## Allele and recoding definition

| Input | REF / dosage-0 allele | ALT / dosage-2 allele |
|---|---|---|
| HapMap | first allele in `alleles` | second allele in `alleles` |
| VCF | `REF` | `ALT` |

`recode_format = "0,1,2"` is the count of ALT alleles. The `"-1,0,1"`
scheme is exactly ALT dosage minus one. PredictProR does not choose REF from the
observed major allele because doing so would make coding change across cohorts.

Mean imputation in the built-in QC path uses the numeric marker mean and does
not round it to a hard genotype. Beagle output is re-imported from its GT field;
DS/GP fields are preserved in the VCF but are not substituted silently for GT.

## Supported format matrix

| Surface | Supported | Explicit boundary |
|---|---|---|
| HapMap containers | `.hmp`, `.hmp.txt`, `.hapmap`, `.txt`, `.tsv`; plain, gzip, or a zip containing one HapMap file | multiple supported files in one zip are rejected |
| HapMap headers | standard 11 columns; position-aware aliases used by GAPIT (`rs`, `assembly`, `panel`) | arbitrary column reordering is rejected |
| HapMap calls | A/C/G/T homozygotes, double-letter or separated diploid calls, IUPAC R/Y/S/W/K/M, documented missing codes | allele-inconsistent calls error by default; `invalid_call="missing"` is opt-in and counted |
| VCF text versions | VCF 4.1 through 4.5 for built-in recoding; Beagle 5.4 is validated with VCF 4.2 and 4.3 GT data | BCF is not accepted |
| VCF GT layouts | GT alone or within colon-delimited FORMAT fields; phased and unphased diploid calls; plain or gzip files | haploid, polyploid, symbolic, and multiallelic dosage rows are excluded and counted |
| Variant alleles | biallelic A/C/G/T sequence alleles, including sequence indels in VCF | symbolic alleles and `*` are excluded from the Beagle route |
| Reference panels | `.vcf`, `.vcf.gz`, or `.bref3` accepted by Beagle | reference genotypes must be phased, diploid, non-missing, and allele/order aligned; PredictProR does not infer strand alignment |

`qc_engine = "r"` is the deterministic default for VCF recoding. The legacy
PLINK route remains available with `qc_engine = "plink"`. LD pruning is not
silently approximated: request the PLINK engine when `ld_pruning = TRUE`.

## Validation layers

1. Unit fixtures cover IUPAC/double-letter calls, declared-allele orientation,
   both recoding schemes, call-rate boundaries, VCF 4.1-4.5, FORMAT position,
   gzip and zip input, missing calls, duplicate/missing IDs, and malformed
   negatives.
2. A fake-Beagle executor tests quoting, paths with spaces, command arguments,
   wrapper and Beagle logs, non-zero exit status, and missing output without a
   network or Java dependency.
3. `tools/audit_genotype_formats_beagle.R` exercises public primary-source
   files and, when the official JAR is present, a real Java/Beagle run.
4. The final source archive must pass `R CMD check`; the archive is inspected
   separately so external corpora and downloaded JARs are never shipped.

## Primary-source corpus used in the external audit

- Beagle 5.4 program and `test.29Oct24.c8e.vcf.gz`, University of Washington:
  <https://faculty.washington.edu/browning/beagle/b5_4.html>
- GA4GH/HTS-specs VCF 4.3 `examples/vcf/simple.vcf`:
  <https://github.com/samtools/hts-specs/blob/master/examples/vcf/simple.vcf>
- GAPIT maize HapMap demonstration file:
  <https://github.com/jiabowang/GAPIT/blob/master/Documents/mdp_genotype_test.hmp.txt>

The GAPIT audit intentionally detects allele-inconsistent calls in that public
file. Strict mode stops and reports examples. The explicit
`invalid_call = "missing"` audit converts 2,277 such cells to missing, records
that count, and verifies direct-HapMap and VCF-round-trip dosage identity. This
is evidence for the policy, not permission to silently repair source data.
